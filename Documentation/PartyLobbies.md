# Adventure lobbies

Open User List > Party > Adventure lobbies. The directory refreshes every ten seconds and supports manual refresh, an activity filter and host/title/dungeon search. Players may advertise Dungeon (with selection of an available configured dungeon), Invasion, World Boss, Alchemy, Poker, Blackjack, Roulette, Lumberjack, House Party, Looting or Cooking. A short title is optional. These are public recruitment listings and use the existing party roster, leader, kick/leave controls and party chat. They do not create a second group or automatically buy into a mini-game.

Only the party leader (or a solo player) may create a listing. Joining requires leaving any other group/lobby first and returning to the open world. Capacity comes from the party configuration, limited by the selected dungeon's maximum party size. Dungeon recruits must meet level, Premium and prerequisite quest requirements. The existing dungeon gate continues to validate all entry requirements and availability when starting the actual run.

Meet host is an explicit action after joining. Ordinary lobbies gather players at the host's current overworld location. Private instances and configured dungeon interiors cannot be entered through this action. Combat, pending death, held dialogue, trading, banking, crafting and mini-game sessions prevent travel. House Party visits use the existing public-house visit flow; closing the house also removes its listing. Joining/visiting does not bypass house privacy or automatically launch a mini-game.

When any party member starts a dungeon, the listing is permanently marked Started - locked. Late joins and lobby teleport requests are rejected on the server, including requests forged while the client still shows an old list. Closing/recreating the listing is necessary for a later run. Listing closure does not dissolve the party. Offline hosts and listings whose host is no longer party leader are removed when the directory is queried. Listings are temporary and end on server restart.

New player-facing text is translated in English, French and Spanish. Rebuild and deploy the client, server and editor together. Automated tests cover the real party membership path, capacity and ownership checks, blocked players, dungeon requirements and lock, stale IDs, logout cleanup, protocol serialization, search/filter combinations and real UI layout/refresh on small and large canvases. Multiplayer travel and authored dungeon gates still require an in-game verification after deployment.
