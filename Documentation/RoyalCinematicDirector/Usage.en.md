# Royal Cinematic Director — initial integrated authoring flow

Open a real map, then open Royal Cinematic Director from the Hub or editor menu. Set scene duration and optional saga/chapter/sequence metadata. Choose personal map Events as actors and define the player's start tile. Draw cardinal tile paths with mouse clicks, move points by dragging, remove with right-click, and reorder from the point list with Alt+Up/Down.

Add camera clips, place their targets on the map, and edit zoom/duration/easing. Add native dialogue, four-way choices, animations, existing sounds/voices and music. Select resources using the resource picker; audio import opens the existing Sound Import tool. Timeline clips can be dragged, resized, duplicated and undone/redone. The map preview uses the editor's actual map renderer; no reference illustration is used as playable scenery.

Save Scene and Map compiles a dedicated local Event page into native commands and sends the map through the existing save tracker. The dedicated scene Event initially sits at tile (0,0); configure its location, trigger, graphic and conditions in the native Event Editor. Add Play Cinematic to any Event, including a quest's common Event, and select this map-local scene. The call waits for scene completion and respects the scene page's server conditions. F5 saves and launches the configured client; log in, stand at authored start positions and trigger the Event. Automatic account login and remote editor-triggered test playback are not implemented.

Dialogue confirmation, choices, route completion and common Events are synchronization barriers. Later timeline time resumes after they complete. Already-started camera/movement can finish during dialogue. For playable interaction, add a common Event clip and enable Allow Player Control during the Event. Existing server conditions, variable checks or quest objectives can wait for the action before returning. The authoring preview pauses at interactive clips; resuming only simulates the response, never executes gameplay.

The player retains native gameplay speed; the five authoring speeds apply to Event actors. Shared/global Events and arbitrary live NPCs cannot be moved by personal scenes. Paths remain map-local and native collisions remain authoritative. Camera state is recipient-only and temporary, with cleanup at completion, release and map/connection changes; saved zoom preferences are not overwritten. There is no client completion/reward packet.

The preview reads a native map render into a bitmap at up to 5 Hz. It estimates movement timing, represents the player with a marker, samples linked native animation sheets and cannot fully reproduce client lighting/effect occlusion or conditional Event page selection. The 1280×720 camera reference can differ from client framing near native map boundaries. Generated commands are regenerated on save; manual advanced command edits are not reverse-imported into the timeline, while native page triggers, conditions and graphics are preserved.

Not implemented in this step: skip/resume, HUD hiding, collective playback, temporary cast spawning, ship following/formations/cannon cinematics, battlefield mass actors, production templates and chapter unlock progression. Chapter metadata is organizational. Existing audio is retained; no Inworld, AI dubbing or paid dependency is introduced. Faithful lore demos require the actual game database and assets, which are not in this checkout.

Run `scripts/Verify-Cinematics.ps1` for builds, compiler/actor/naval tests and a hidden WinForms input/layout smoke test. `-SkipAnalyzers` reproduces the analyzer-disabled local verification. A synthetic layout image is not a connected game screenshot. The optional native GPU check uses an external map export from `scripts/Export-CinematicMapFixture.py` and the smoke executable's `--native-map` mode with copied existing resources; see `Validation.md`. Complete the connected/multiplayer checklist before release.
# In-development additions: advanced cinema and chapters

Presentation clips interpolate letterbox/fade/shake and temporarily hide the HUD; values hold until the next presentation clip or cleanup. Native dialogues, choices and mandatory UI remain visible above effects. Actor-follow cameras use tile framing offsets; attached native animations use pixel offsets. Shot presets and thirteen editable templates are starting points, not the specialized battle modes. Waypoints support native 100 ms pauses and facing; speed changes and FacePlayer require personal Event actors. Timeline markers can be dragged by their orange header handle. Movement preview timing remains approximate.

Story and Chapters stores ordered scenes as a native common Event, with Project/Saga organization, personal boolean unlock/completion guards, an optional native quest offer/start, and common Events before/after entries. Already active/completed quests are not offered again. Travel and scene anchors stay explicit. Regeneration preserves page conditions/triggers and replaces generated commands. Call the chapter through Start Cinematic Chapter or existing quest/Event hooks. Rewards and idempotence stay in native quests/Events.

Stop Cinematic cancels the scene's calling stack and restores state. Wait For Cinematic observes active scenes owned by other Events of the same player; timeout, interruption or a superseded run aborts its caller. No active scene means no wait, not proof of quest success. These commands do not implement persistent mid-scene resume. Matching editor/client/server builds are required. Builds passed, but new gameplay/automated tests are deferred until the requested grouped campaign.


Every Camera clip now supports Flat 2D or Perspective 2.5D, for land, interior, battlefield and naval scenes. Select Projection, then heading, eye height (tiles), pitch and field of view. Camera View previews the loaded editor map in perspective; switch to the overview to edit routes and see the heading/FOV cone. Shot presets adjust height/pitch when perspective is already selected. Subsequent clips can return to 2D. Lens values interpolate over the native clip duration.

This reuses existing cannon projection, map tiles, native entity appearance/equipment and animation draw paths. It projects flat ground and upright images; it does not create modeled 3D assets. The client only uses already received maps. Dialogue, choices and authoritative gameplay continue through the native systems. The editor preview does not simulate player equipment, collisions, network waits, adjacent maps, animated weather or dynamic lighting. The client perspective reuses native fog, tint and weather with uniform ambient brightness; projected dynamic lights and housing furniture remain incomplete. Unsupported devices fall back to 2D, with editor status/client logging. Actual Intel DLL compatibility remains to be checked during the final grouped campaign.


Gameplay, Condition and Quest tracks reuse native authoritative Events and quest state. Gameplay calls a common Event, optionally releasing player control while it runs, or sets a personal boolean without party synchronization. Condition waits for a personal flag, active/completed quest, current task or task passed (including quest completion). Select the kind, then Resources to pick existing IDs. Maximum wait bounds the server pause; the clip’s graphic duration remains its timeline slot and does not prove success. Later commands resume only when the condition holds. A timeout cancels the entire caller and restores the scene instead of executing later progression. Conditions poll at most once per 100 ms without a command busy loop or client-success packet. Enable player control during the wait to let native gameplay/Events set the condition. The editor preview pauses at these barriers and does not simulate their success. Quest can offer/start a quest when neither active nor completed, or finish only its current EventDriven objective. Server command 1078 rechecks the objective type at execution; passed/completed tasks are idempotent no-ops. Combat/gathering/dungeon/naval objectives retain their existing progression systems, callbacks and rewards.


Environment clips apply recipient-only fog, RGB tint, brightness and configured weather. Select the clip, open Scene atmosphere settings and use Resources to choose an existing fog texture. Empty fog filenames remove fog. Weather can remain normal, clear, or activate the map’s existing outdoor weather configuration. This introduces no new weather assets or server time/physics changes; rain/thunder use already configured audio. Fog/tint/weather retain native transitions; the graphic clip duration is not an added atmosphere interpolation curve. The override persists until replaced, explicitly restored, or the scene finishes/is interrupted. Restoration reads the current live map/invasion environment instead of rewriting their configuration. Editor previews show fog/tint/brightness in flat and perspective camera views, not weather particles or dynamic lighting.


Naval Scene reads existing navigation/catalogue models without changing their configuration. On an existing native Ocean-folder map, add Scenic Vessel, pick its model and place it with the mouse. At most 16 scenic vessels fit within the 64 total actors. Existing ocean textures and .naval.json/.effects.json metadata are reused; client/editor share atlas readers and slice geometry. Missing artwork remains explicit: 2D prototype/footprint, no arbitrary interpretation of unverified ocean atlases in perspective.

Naval paths use direct water segments, clip duration/easing and native hull-footprint validation at the start and throughout the path. Walking waypoint actions and cross-map sailing are not added. Fleet Formation retains the anchor’s stable id and existing path; Group Path translates its path onto the other members. Actor clips show/hide reinforcements. Either camera projection can follow a scenic vessel. Naval Effects clips set normal/damaged/sinking appearance, fire port/starboard, hit a vessel or a clicked map point. Appearance, broadsides and hull impacts can synchronize across the fleet. Cosmetic cannonballs reuse native direction/sweep, stop at terrain/range and cause no gameplay damage. Existing configured sounds/graphics and optional native impact animations are reused. Attached animations follow the vessel. Effects/balls are bounded at 128 each, with 20 s effect and 30 s ball lifetimes.

Scenic vessels have no captain/crew, ownership, cargo, AI, cannon rights, rewards or persisted ship state. They remain separate from the playable fleet and disappear on finish/interruption. Use native common Events and after-scene/chapter callbacks for actual playable combat/boarding, retaining native ownership/instance/munition rules. No automatic conversion into a playable ship, boarding, server deployment or player teleport is introduced. Editor shot playback is estimated and silent; network timing/audio/Intel performance/actual combat transitions await the final campaign. Battlefield mode currently organizes the existing temporary actors/formations; dedicated land-battle tools are the next block.
