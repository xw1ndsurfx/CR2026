# Royal Cinematic Director — creating and editing scenes

The main toolbar follows **Create → Open scene… → Actors and paths → Directing → Preview / test → Save**. **Edit**, **Files** and **View** contain the supporting commands. The Director uses the game's map and resources; the reference illustration is not playable scenery.

## Create, save and test a scene

1. Open a real map, then open **Royal Cinematic Director** from the Hub or editor menu.
2. Select **Create → New scene…**, **Land battle…** or **Naval battle…**. Enter a name, choose the scene type and select **Camera projection → 2D view** or **2.5D perspective**. Projection is independent of scene type. Battle starters prepare editable camera/presentation shots; add the actual actors and resources afterward. Naval scenes require a real map in the native `Ocean` folder.
3. **Create → Guided creator…** also offers the projection choice for its narrative scenarios. **From a description…** prepares an editable scene from local keywords and existing resources; complete unresolved choices before generating. It does not generate a complete fleet automatically. **Edit → Scene properties** contains duration and optional saga/chapter/sequence metadata; those text fields alone do not trigger quests.
4. Define the player's start tile and use **Actors and paths** to add personal Event actors, **Temporary NPC actor**, formations and **Movement** clips. Draw cardinal tile paths with mouse clicks, drag points to move them, remove with right-click, or reorder in the point list with Alt+Up/Down. Shared/global Events and arbitrary live NPCs are not moved by personal scenes.
5. Use **Directing → Camera** to add a 2D or 2.5D shot. Place its target on the map and edit zoom, duration and easing. Cameras added without an explicit projection choice inherit the preceding shot's projection. Check **Camera preview** to inspect framing; uncheck it to place actors and paths.
6. **Directing** provides dialogue, four-way choices, effects, presentation, music and **Sound / voice**. **Choose existing resource** selects authored resources. The left library also supports dropping characters, effects and audio onto the map or timeline. **Import existing audio files…** opens the existing Sound Import tool.
7. Drag and resize timeline clips; use Ctrl+wheel for timeline zoom. Undo/redo are in **Edit**; playback, stop and 50 ms stepping are in **Preview / test**.
8. **Save** compiles native commands and sends the map through its normal network save. A new scene receives a dedicated local Event, initially at tile (0,0); configure its location, trigger, graphic and conditions in the native Event Editor. Reopening a saved scene retains that Event's identity.
9. Add **Play Cinematic** to an Event, including a quest's common Event, and select the map-local scene. The call waits for completion and respects the scene page's server conditions. **Preview / test → Test in game (F5)** saves and launches the configured client; log in, stand at the authored start positions and trigger the Event. This does not automatically log in a test account or bypass server conditions.

## Reopen and edit a saved scene

Open its source map in the Game Editor, then click **Open scene…** and search by name. Saved scenes also appear in the explorer under **Saved scenes on this map**. Selection retains the Event ID even when two scenes have the same name, and editing uses a detached source copy until you save.

Edit actors, shots or dialogue and click **Save**. The same Event is updated, retaining its position, trigger, conditions and other native page metadata. If the source Event has been deleted, the Director reports it as unavailable. Before replacing an edited scene, the prompt lets you save, discard changes or cancel and continue editing.

**Files → Import JSON…** opens a scene file as a new copy; **Export JSON…** writes a file. Import keeps the map referenced by the file and does not link the copy to the original Event. Open the corresponding map before saving an import. Use **Open scene…** when the intention is to update an already saved scene without creating another one.

## Interaction and limits

Dialogue confirmation, choices, route completion and common Events are synchronization barriers. Later timeline time resumes after they complete. Already-started camera/movement can finish during dialogue. For playable interaction, add a common Event clip and enable Allow Player Control during the Event. Existing server conditions, variable checks or quest objectives can wait for the action before returning. The authoring preview pauses at interactive clips; resuming only simulates the response, never executes gameplay.

The player retains native gameplay speed; the five authoring speeds apply to Event actors. Shared/global Events and arbitrary live NPCs cannot be moved by personal scenes. Paths remain map-local and native collisions remain authoritative. Camera state is recipient-only and temporary, with cleanup at completion, release and map/connection changes; saved zoom preferences are not overwritten. There is no client completion/reward packet.

The preview reads a native map render into a bitmap at up to 5 Hz. It estimates movement timing, represents the player with a marker, samples linked native animation sheets and cannot fully reproduce client lighting/effect occlusion or conditional Event page selection. The 1280×720 camera reference can differ from client framing near native map boundaries. Generated commands are regenerated on save; manual advanced command edits are not reverse-imported into the timeline, while native page triggers, conditions and graphics are preserved.

Presentation skipping, temporary HUD hiding, temporary actors, land/naval formations, battlefield effects and chapter progression are implemented in the code and described below. Persistent mid-scene resume and coordinated collective playback remain incomplete. Saga/chapter/sequence text on an individual scene is still organizational; chapter orchestration uses the separate chapter tool. Production scenes and faithful lore demos require the actual maps, characters and resources chosen by the team. Existing audio is retained; no Inworld, AI dubbing or paid dependency is introduced.

Run `scripts/Verify-Cinematics.ps1` for builds, compiler/actor/naval tests and a hidden WinForms input/layout smoke test. `-SkipAnalyzers` reproduces the analyzer-disabled local verification. A synthetic layout image is not a connected game screenshot. The optional native GPU check uses an external map export from `scripts/Export-CinematicMapFixture.py` and the smoke executable's `--native-map` mode with copied existing resources; see `Validation.md`. Complete the connected/multiplayer checklist before release.
## Actors and advanced cinema

**Actors and paths → Temporary NPC actor** uses an existing NPC sprite definition to create a recipient-only visual actor. These actors have no combat AI or loot and are removed at scene completion/interruption. Formations and translated group paths remain bounded by the Director's 64 total actor limit.

Presentation clips interpolate letterbox/fade/shake and temporarily hide the HUD; values hold until the next presentation clip or cleanup. Native dialogues, choices and mandatory UI remain visible above effects. Actor-follow cameras use tile framing offsets; attached native animations use pixel offsets. Shot presets and thirteen editable templates provide editable starting points; configure vessels, actors and battle actions with the dedicated tools below. Waypoints support native 100 ms pauses and facing; speed changes and FacePlayer require personal Event actors. Timeline markers can be dragged by their orange header handle. Movement preview timing remains approximate.

## Story and chapters

Open **Files → Story and chapters**, then **New chapter**. Enter its name in **Chapter properties**; project and saga are optional organization fields. Use **Add a loaded scene** to choose scenes already saved and loaded in the editor, then order them with the movement buttons. If a scene is missing, save it and load its map first.

Click **Save chapter as common Event**. A new chapter without custom tracking gets its own personal completion flag automatically; the author does not need to create or select a variable. The editor waits for the server's creation/save confirmations for the flag and then the chapter content before reporting **Chapter saved**. If the connection or confirmation fails, edits remain open and are not treated as saved. Existing chapters keep their Event identity and established progress tracking.

**Advanced options** is optional. Named resource choices expose an unlock condition, custom completion tracking, Events before/after each scene or at chapter completion, and the **Advanced Event editor**. Unlock and completion tracking must be distinct. **Completion tracking → Automatic (recommended)** selects a dedicated personal flag again. The optional quest and replay setting remain in the ordinary chapter properties.

Chapters store ordered scenes in a native common Event. Regeneration preserves native page conditions/triggers and replaces generated commands. Call the chapter through **Start Cinematic Chapter** or existing quest/Event hooks. Already active/completed quests are not offered again. Before/after Events provide explicit travel and gameplay links; scene start positions are still checked. Rewards and idempotence remain in native quests/Events.

Stop Cinematic cancels the scene's calling stack and restores state. Wait For Cinematic observes active scenes owned by other Events of the same player; timeout, interruption or a superseded run aborts its caller. No active scene means no wait, not proof of quest success. These commands do not implement persistent mid-scene resume.

This guide describes behavior implemented in the code; it is not evidence of GPU, multiplayer or in-game validation. See `Interactive-QA.fr.md` for recorded observations and `Validation.md` for connected acceptance checks. Use matching editor/client/server builds.

## 2D and 2.5D cameras

Choose **2D view** or **2.5D perspective** at creation for any scene type, including land and naval scenes. For an existing Camera clip, change **Camera projection**, then heading, eye height (tiles), pitch and field of view. **Directing → Camera** also offers explicit 2D and 2.5D shot creation. **Camera preview** shows the loaded editor map using that projection; switch to the overview to edit routes and see the heading/FOV cone. Shot presets adjust height/pitch when perspective is already selected. Subsequent clips can return to 2D. Lens values interpolate over the native clip duration.

This reuses existing cannon projection, map tiles, native entity appearance/equipment and animation draw paths. It projects flat ground and upright images; it does not create modeled 3D assets. The client only uses already received maps. Dialogue, choices and authoritative gameplay continue through the native systems. The editor preview does not simulate player equipment, collisions, network waits, adjacent maps, animated weather or dynamic lighting. The client perspective reuses native fog, tint and weather with uniform ambient brightness; projected dynamic lights and housing furniture remain incomplete. Unsupported devices fall back to 2D, with editor status/client logging. Actual Intel DLL compatibility remains to be checked during the final grouped campaign.


Gameplay, Condition and Quest tracks reuse native authoritative Events and quest state. Gameplay calls a common Event, optionally releasing player control while it runs, or sets a personal boolean without party synchronization. Condition waits for a personal flag, active/completed quest, current task or task passed (including quest completion). Select the kind, then **Choose existing resource** to select configured resources. Maximum wait bounds the server pause; the clip’s graphic duration remains its timeline slot and does not prove success. Later commands resume only when the condition holds. A timeout cancels the entire caller and restores the scene instead of executing later progression. Conditions poll at most once per 100 ms without a command busy loop or client-success packet. Enable player control during the wait to let native gameplay/Events set the condition. The editor preview pauses at these barriers and does not simulate their success. Quest can offer/start a quest when neither active nor completed, or finish only its current EventDriven objective. Server command 1078 rechecks the objective type at execution; passed/completed tasks are idempotent no-ops. Combat/gathering/dungeon/naval objectives retain their existing progression systems, callbacks and rewards.


Environment clips apply recipient-only fog, RGB tint, brightness and configured weather. Select the clip, open Scene atmosphere settings and use **Choose existing resource** to choose an existing fog texture. Empty fog filenames remove fog. Weather can remain normal, clear, or activate the map’s existing outdoor weather configuration. This introduces no new weather assets or server time/physics changes; rain/thunder use already configured audio. Fog/tint/weather retain native transitions; the graphic clip duration is not an added atmosphere interpolation curve. The override persists until replaced, explicitly restored, or the scene finishes/is interrupted. Restoration reads the current live map/invasion environment instead of rewriting their configuration. Editor previews show fog/tint/brightness in flat and perspective camera views, not weather particles or dynamic lighting.


## Naval battle

Open a real map in the native **Ocean** folder, select **Create → Naval battle…**, and choose 2D or 2.5D. The Director prepares editable shots. Then use **Actors and paths → Ships and fleets → Scenic vessel**, choose an existing model and place it with the mouse. **Create fleet formation** uses the selected vessel as its anchor. Models are read from existing navigation/catalogue configuration without changing it; adding a vessel requires an available model and a valid hull footprint on the map. At most 16 scenic vessels fit within the 64 total actors. Existing ocean textures and `.naval.json`/`.effects.json` metadata are reused; client/editor share atlas readers and slice geometry. Missing artwork remains explicit: 2D prototype/footprint, no arbitrary interpretation of unverified ocean atlases in perspective.

Naval paths use direct water segments, clip duration/easing and native hull-footprint validation at the start and throughout the path. Walking waypoint actions and cross-map sailing are not added. **Create fleet formation** retains the anchor’s stable id and existing path; **Copy path to group** translates its path onto the other members. Actor clips show/hide reinforcements. Either camera projection can follow a scenic vessel. Naval Effects clips set normal/damaged/sinking appearance, fire port/starboard, hit a vessel or a clicked map point. Appearance, broadsides and hull impacts can synchronize across the fleet. Cosmetic cannonballs reuse native direction/sweep, stop at terrain/range and cause no gameplay damage. Existing configured sounds/graphics and optional native impact animations are reused. Attached animations follow the vessel. Effects/balls are bounded at 128 each, with 20 s effect and 30 s ball lifetimes.

Scenic vessels have no captain/crew, ownership, cargo, AI, cannon rights, rewards or persisted ship state. They remain separate from the playable fleet and disappear on finish/interruption. Use native common Events and after-scene/chapter callbacks for actual playable combat/boarding, retaining native ownership/instance/munition rules. No automatic conversion into a playable ship, boarding, server deployment or player teleport is introduced. Editor shot playback is estimated and silent; network timing/audio/Intel performance/actual combat transitions await the final campaign.


## Land battle and playable transition

**Create → Land battle…** prepares editable shots. Add actors/formations under **Actors and paths**, then open **Directing → Battlefield scene** for **Group animation**, **Charge along group route** (native fastest Event route plus translated group copies) and **Reinforcement cue** (hidden-at-start members plus visibility clips at the cursor; prior visibility clips still apply). Pick existing NPC definitions for soldiers, cavalry or engines when such assets exist. No new artwork, AI or loot is introduced; total actors remain bounded at 64.

Projectile / Moving Effect selects a native animation, source actor/group, mouse target, duration up to 30 s, easing, optional rotation and arc height 0–8 tiles. **Choose existing resource** selects travel and optional arrival animations. Travel frames loop until arrival, respecting layers with rotations disabled. These are theatrical effects, including for scenic vessels, with no gameplay projectile collision/damage/quest credit; arcs may cross scenery. Client/editor reuse native frames and matching arc/easing parameters. Effects are bounded and the compiler caps generated commands at 8192.

Create Playable-phase Trigger saves a native common Event that plays the scene and then calls the chosen existing gameplay Event. Link it through Events/Quests. The cinematic restores its state before the callback; the common caller avoids running that callback inside an active cinematic during map/instance travel. It creates no implicit combat, rewards, ship conversion or player teleport. Both staging modes share this hook. These additions compile; no new in-game validation has run yet.
## Skipping presentation

The scene property “Allow skipping the presentation” enables a command in the Escape menu and cinematic dialogue window. It defaults to disabled. The server checks scene ownership and run version before accepting the request.

Skipping restores the camera, removes presentation effects and scenic vessels, and omits timeline waits and non-choice scene dialogue. Choices, actor routes and route waits, conditions, gameplay Events and quest objectives remain required. Dialogue and waits inside called gameplay Events are retained. Completion still runs through those server commands; the button never directly completes quests or rewards. Already playing sounds retain their native duration.
